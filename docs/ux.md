# 创作工作台交互设计

## 1. 主路径与信息架构

围绕作者完成一次章节创作组织页面：

```text
项目列表
└── 小说工作区
    ├── 概览：有效正文进度、待审提案、失败/失效提醒
    ├── 设定：人物 / 世界 / 事件 / 伏笔
    ├── 规划：创意、卷目标、章纲、规划提案
    ├── 章节：编辑、候选比较、审稿与验收、版本历史
    └── 任务与记忆：任务记录、来源查询、有效记忆
```

MVP 不单建图谱中心、时间线中心和复杂 Agent 控制台。运行信息在作者需要决策的位置呈现，任务记录提供进一步诊断。

## 2. 核心布局

桌面工作区采用三栏：左侧项目资产与卷章导航，中间正文/设定编辑，右侧当前任务或审阅面板。右栏可折叠，窄屏转为单栏加页签；不要让作者为了保存正文必须横向滚动。

章节页顶部固定呈现章名、正式状态、是否有未验收修改和保存状态。任务状态与章节状态分别显示，例如“正式稿有效 · 草稿有修改 · AI 等待验收”，避免单一“已完成”掩盖状态差异。

## 3. 关键操作

### 新建项目与准备规划

输入标题、创意，选择可用的玄幻规则包和风格。创建后引导作者补充关键人物、世界规则、卷目标和第一章纲；可选择手工录入或提交规划任务。规划提案显示所有拟新增/修改对象，作者整批接纳后进入正式设定。

不要求作者先配置六个 Agent。模型路由与预算通过简洁配置入口设置；使用 Fake 时持续显示“演示模型”，不能把固定假输出呈现为真实创作能力。

### 生成候选

作者在章节页设置目标汉字数、模型配置和预算，看到当前章纲及有效上下文摘要后提交。提交按钮防连点并固定幂等键，网络超时用相同键查询/重放，不新建多次任务。

提交成功立刻显示持久化任务 ID、当前步骤和取消入口；页面切换或刷新后从服务端恢复。进度显示“写作 / 编辑 / 审阅 / 提取记忆”，不显示没有依据的百分比。

### 编辑与比较

中间编辑器默认展示当前草稿；AI 候选在独立比较视图打开，生成完成不替换编辑区。可比较候选、当前草稿和正式稿，版本标签显示作者类型、生成时间与来源任务。

保存是显式操作，显示未保存、保存中、已保存和冲突状态。存在未保存内容时离开页面提示；保存请求必须携带基线。多标签页冲突时保留本地输入，可复制或比较后另存，不提供无版本检查的强制覆盖。

“采用后编辑”将候选内容加载并保存为新人工版本，提示需重新审阅。若有未保存编辑先处理这些内容；禁止直接把编辑器内存文本当成已验收正文。

### 人工验收

验收视图并列显示：

- 确切候选版本的正文差异与实际长度。
- 硬规则检查结果、Critic 警告及对应段落/证据。
- 待新增/修改的人物状态、事件、伏笔和章节摘要，带来源。
- 若替换历史内容，显示将失效的后续章节与记忆范围。

按钮为“验收为正式稿”和“拒绝候选”。一般质量警告需作者明确确认；硬规则和结构错误阻止验收。正文或记忆需调整时，回到编辑/设定流程生成新提案；MVP 不让作者在同一提案里随意删除部分操作。

成功后显示新的正式修订和正式稿来源；拒绝不改变当前草稿、正式稿或记忆。作者看到的是“正式稿”，不使用暗示已发布到外部平台的文案。

## 4. 状态与恢复

| 场景 | 页面反馈 | 可执行操作 |
| --- | --- | --- |
| 暂无项目/章纲 | 清晰空状态与下一步，不出现空图表 | 新建项目、补充章纲 |
| 模型未配置 | 生成前定位配置问题 | 选择 Fake 演示或填写后端支持的配置 |
| 任务执行中 | 当前步骤、累计已知用量、取消状态 | 离开页面、返回查询、取消 |
| 供应商失败/预算耗尽 | 分类错误、用量未知提示、候选保留情况 | 修改配置/预算后显式重试新任务 |
| 请求结果不明 | 显示正在核实提交状态 | 使用原幂等键重放，不重新生成键 |
| 候选过期 | 说明哪项正式修订或草稿变了，结果可读 | 采用内容后重新审阅，或重新生成 |
| 正式历史被修订 | 列出需重新确认的后续章节 | 按章序审阅原文或重写 |
| 取消等待中 | 说明已请求停止，当前供应商调用可能仍完成并计费 | 等待服务端最终状态 |
| 导出受阻 | 显示失效章节列表 | 修复有效链路后导出 |

## 5. 记忆可解释性与可访问性

上下文面板显示实际使用的资产版本、记忆来源和章节边界，点击可定位原文；检索结果展示来源而不是单独的一段“系统记忆”。作者修改正式设定时，表单明确显示生效章和历史影响。

所有主要操作支持键盘、明确标签与焦点反馈；错误信息不只用颜色表达。比较视图提供文字差异和版本信息，图形不作为唯一入口。正文使用适合长时间阅读的行宽和字号，任务日志默认折叠。

## 6. 页面验收

至少演示四条完整路径：首次建项目并验收第一章；修改 AI 稿后重新审阅；任务失败/取消后恢复；两个标签页导致冲突且不丢稿。细化场景见 [验证策略](validation.md)，工程交付顺序见 [实施计划](implementation-plan.md)。
