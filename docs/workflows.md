# Agent 协议与持久化工作流

## 1. 能力边界

Agent 是类型化执行单元，可以由普通异步函数、对象或后续框架节点实现。其价值来自明确职责、可验证输出和受限权限，而不是特定类名或自主循环。

调用方向固定为：工作流调度 Runtime，Runtime 调用网关。工作流负责选择下一步；模型不自行启动无限任务。

| 角色 | 输入 | 输出 | MVP 权限 |
| --- | --- | --- | --- |
| Planner | 创意、约束、规则包、已有资产/规划快照 | 有限的设定与卷章规划操作 | 读取快照、输出计划提案 |
| Writer | 章节纲/场景计划、有效记忆、风格、目标长度 | Markdown 候选正文 | 读取快照、输出正文 |
| Editor | Writer 候选、约束、上下文 | 一次编辑后的候选及编辑说明 | 只生成新版本，不覆盖草稿 |
| Critic | 最终候选、规则与场景目标 | 带位置/证据的问题和建议 | 只读评审，不决定验收 |
| Memory Extractor | 最终候选、有效资产、章节边界 | 摘要、事实和资产变更提案 | 输出结构化候选，不写正式记忆 |
| Director | 长期目标与进度 | 后续阶段的推进计划 | MVP 不实现 |

样稿中的 Memory Agent 在这里称 Memory Extractor，突出提取与提交分离。工具权限在 Runtime 中实施；MVP 优先给固定上下文，不开放通用 shell、HTTP、文件或数据库工具。

## 2. 输入输出契约

`AgentContext` 至少包括：

```text
novel_id, run_id, step, task_kind
base_canon_revision, chapter_id?, base_draft_version_id?
snapshot_id / input_hash
chapter_outline, scene_plan, memory_context, asset_versions
constraints, style_profile, plugin_id, plugin_version
prompt_id, prompt_version
remaining_budget, cancellation_token
```

Context Builder 产出的对象是只读快照，不能把数据库 session、环境变量或供应商密钥交给 Agent。

`AgentResult` 使用区分成功/失败的联合类型：

- 成功：`output_type`、`output`、`warnings[]`、`source_refs[]`、`usage`、`model_metadata`。
- 失败：`error_code`、`retryable`、`message`、`usage`、`outcome_unknown`。

正文与结构化提案分别校验。JSON 可解析不代表领域有效；Runtime 校验结构，应用再校验项目归属、引用、规则与版本。模型自由文本日志不作为程序控制字段。

提示词作为仓库版本化资源保存，记录模板 ID、版本和渲染输入哈希。任务保留当时的输入/配置快照，不要求供应商生成结果可确定性复现；回归测试使用 Fake 适配器。

## 3. 三条 MVP 工作流

### `plan_novel`

校验预算与正式修订 → 构建规划上下文 → Planner → 结构/引用/规则校验 → 持久化 `plan` ChangeSet → `awaiting_review`。

规划输出是作者要求范围内的设定、卷章和大纲候选。已存在数据只允许在提案中明确指定修订目标，不能根据相似名字自动覆盖。接纳前显示新建/修改清单及历史影响范围。

### `generate_chapter`

前置：章节纲存在，前序章节已连续有效验收，无其他排队/执行任务，预算合法。

```text
Context Builder
  → Writer → 保存初始候选版本
  → Editor（一次）→ 保存最终候选版本
  → 硬规则检查 + Critic
  → Memory Extractor（针对最终候选）
  → 校验并持久化 chapter ChangeSet
  → awaiting_review
```

Editor 之后的版本是审稿、摘要和事实提取的唯一正文来源。Critic 发现一般质量问题时保留警告供作者判断，不自动进入改稿循环。硬规则/结构问题在有限修复仍失败后结束为 `failed`。

### `review_chapter`

作者保存人工正文后指定该 `draft_version_id`：Context Builder → 硬规则检查 + Critic → Memory Extractor → `chapter` ChangeSet → `awaiting_review`。

此工作流不调用 Writer/Editor，候选就是该不可变人工版本。用于纯手写作品、修改候选后的重新审阅，以及历史章节重新确认。若用户在任务期间又保存了新草稿，旧提案不可直接验收。

作者可将候选复制到编辑区再保存，这会产生新的人工版本；旧提案随草稿基线变化过期。任何正文修改都需要对新版本重新审阅和提取记忆。

## 4. 任务状态机

| 状态 | 含义 | 允许的下一状态 |
| --- | --- | --- |
| `queued` | 已持久化，等待 worker | `running`、`cancelled`、`stale` |
| `running` | 有租约，正在执行步骤 | `awaiting_review`、`failed`、`cancelled`、`stale` |
| `awaiting_review` | 候选与提案已保存，等待作者 | `succeeded`、`cancelled`、`stale` |
| `succeeded` | 作者已验收，正式数据已提交 | 无 |
| `failed` | 执行失败，保留诊断与用量 | 无 |
| `cancelled` | 作者取消执行或拒绝提案 | 无 |
| `stale` | 正式修订/草稿基线变化，结果只读 | 无 |

拒绝提案时 ChangeSet 为 `rejected`，Run 为 `cancelled`，`reason=rejected_by_author`。显式取消待审任务也拒绝其提案；单纯取消不代表删除候选。终态不可复活；重试创建新 Run，并记录 `retry_of_run_id`。

worker 在开始、每次模型调用前后、形成提案前检查正式修订、草稿指针和取消标记。验收端必须独立再查，不能因为任务已进入待审就相信旧结果仍有效。

## 5. 上下文与记忆

输入构建顺序：

1. 固定系统指令与输出 schema；预算超限时不能截断它们。
2. 作者硬约束、规则包、目标章节纲与场景计划。
3. 按目标章时间边界选择的人物/世界状态、未解决伏笔。
4. 最近有效已验收章节摘要和相关记忆；每项带来源 ID、章节和有效状态。
5. 如有基础草稿，加入明确标记的草稿资料；未来章纲可作为计划提供，但不得当成已发生事实。

先为输出和网关安全余量预留 token，再按优先级分配输入。必须内容本身超限时返回 `context_too_large`，提供压缩设定/降低范围建议，不静默丢弃硬约束。可选检索项截断应记录被省略项与依据。

检索至少使用 `novel_id`、目标章边界和来源有效性三重限制。所有文本块标为资料，不能扩展权限。快照随任务持久化，以便解释“本次为什么用了这条设定”。

## 6. 领取、检查点与恢复

- API 只创建任务，worker 用行锁和租约领取。领取/重领递增 `lease_generation`，保存步骤输出与检查点时以当前租约代数和 `running` 状态校验写入；丢失租约的旧 worker 即使收到模型响应，也不能推进任务或创建待审提案。租约心跳减少正常长请求被误认领。
- 恢复时检查已成功步骤的持久化输出，不重复调用已完成模型步骤；按检查点继续。
- 模型调用前先持久化 `StepAttempt` 和预算预留。若调用已发出但结果未可靠保存，记录 `outcome_unknown`，不得假定没有计费。
- 未知结果或未知计费场景结束为 `failed` 并要求显式重试；不盲目自动重发可能已完成的请求。已确定未发送的请求可重领继续。
- 租约重领不能阻止旧供应商请求继续在外部运行，但不会自动发起第二次未知请求；晚到的结果不得由旧 worker 写入正式进度。
- 不承诺外部模型“恰好一次”执行。数据库验收通过事务、状态校验和幂等记录实现一次生效。

## 7. 重试、取消与预算

| 情况 | 策略 |
| --- | --- |
| 确认未完成的临时超时、限流、供应商暂时错误 | 有限退避重试；尊重可获得的供应商重试信息 |
| 结构化输出不合法 | 最多一次受约束修复，仍计入尝试和预算 |
| 认证失败、能力不支持、权限/硬规则问题 | 不自动重试，返回可操作错误 |
| 上下文或预算不足 | 调用前失败，不自行扩大预算或切更贵模型 |
| 结果未知、用量未知 | 保留预留与未知标志，停止自动重试 |

默认每个模型步骤最多 `2` 次尝试，格式修复包含其中；运行级还限制总调用数和总 token 预算。降级模型必须预先配置并在提交时允许，模型变化写入尝试记录，不能静默替换能力或计价。

每次请求校验剩余调用数、输入估算、输出上限和价格快照（若存在）。已用加预留超限则停止。token 和费用估算不能被描述为供应商账单的绝对保证；真实价格或用量不可得时明确标未知，不以 `0` 代替。预算限制禁止继续发起请求，不能撤销已在供应商执行的费用。

取消是持久化的协作式请求：网关支持时尝试中止，随后禁止启动新步骤；正在进行的请求可能仍计费。最终状态转换在数据库锁下再次检查取消标记，防止取消后又提交待审结果。若验收已经提交，取消返回状态冲突，不能撤销正式数据。
