# 原始样稿审阅与设计整合

历史审阅范围：原始样稿目录中的全部 8 份 Markdown。审阅日期：2026-10-21。正式启动时样稿目录已不存在，本文保留审阅结论、原文名称和替代入口；原文不再是仓库依赖。本文不是业务代码的实现报告。

## 1. 整体判断

原稿提供了明确方向：个人创作、长篇一致性、模型供应商解耦、题材与文风分离，以及人类决策权。主要不足在于这些方向尚未转化为可以共同执行的产品边界、领域契约和验收任务。

本文的优先级用于判断“若直接按样稿实现会怎样”：**关键**代表可能破坏正文/记忆或作者控制，**高**代表明显影响可交付性，**中**代表造成实现歧义与维护负担。它们是设计审阅结论，不是已发生的软件漏洞。

## 2. 主要发现

| 编号 / 优先级 | 原稿依据与问题 | 新基线如何处理 |
| --- | --- | --- |
| R01 / 关键 | PRD §6、数据库 §5：生成后 Memory 自动更新资产；没有作者接纳门槛，也没有规定废稿和人工改稿的记忆如何处理 | [领域事务](domain-model.md#4-事务与并发) 将候选与正式内容分开，原子验收；[工作流](workflows.md#3-三条-mvp-工作流) 增加人工正文审阅 |
| R02 / 关键 | 数据库 §5–6：正文版本与人物/世界状态分开描述，没有联合回滚、过期检测或来源退役策略 | `canon_revision`、草稿基线、不可变版本、来源边界；历史修改使下游失效，而不是仅替换正文指针 |
| R03 / 关键 | API §4–7：返回“running”但没有持久化领取、崩溃恢复、取消竞态、幂等和预算 | [工作流状态机与恢复](workflows.md)、[API 通用约定](api.md#1-通用约定) 和 V08–V14 明确这些契约 |
| R04 / 高 | PRD §11 与路线图里单章、第一卷、10 万字、百万字混合；MVP 同时承载图谱、多题材和多存储 | [产品范围](product.md#2-阶段边界) 划分 MVP、长篇实验和后续能力，T10 单独验证 10 万汉字 |
| R05 / 高 | PRD §12 平铺 `frontend/backend/core`；技术设计 §2 使用 `apps/packages`；启动文档读路径也与当时的样稿目录不符 | [唯一目标目录](architecture.md#1-架构选择) 与 [导航](README.md)；工程落地状态以实施计划和验证记录为准 |
| R06 / 高 | PRD §12、技术设计 §9、路线图的前后端/Runtime 开发顺序不同；“项目可启动”等标准不足以验收 | [T00–T10](implementation-plan.md) 统一依赖、交付物、排除项与业务场景检查 |
| R07 / 高 | Agent 协议 §7 允许 Writer `save_chapter`，但没有候选写入与正式提交权限区分；启动文档将网关、Runtime、Workflow 的箭头写成另一方向 | [架构边界](architecture.md#2-调用和依赖方向) 固定实际调用方向；Agent 仅输出候选，由应用持久化和验收 |
| R08 / 高 | 技术设计 §3–4、数据库 §1/3/4：直接引入 PostgreSQL/Redis/Qdrant，Redis 保存任务状态，却没有重建和一致性策略 | [D02](decisions.md#d02postgresql-是唯一权威存储) 以 PostgreSQL 为权威；派生索引后续使用 outbox，不在首版承担双写 |
| R09 / 高 | API §5 的链路省略 Critic，其他文档有；Writer 输入要求 Scene Plan，但数据与工作流未保证提供 | [三条工作流](workflows.md#3-三条-mvp-工作流) 统一最终稿来源、场景计划、审稿与提取顺序 |
| R10 / 中 | PRD/技术/数据库/API 分别使用 `genre`、`genre_plugin`、`style`、`style_profile`；Scene、Volume、Relationship 在各处出现不一致 | [领域模型](domain-model.md) 固定名称和归属，场景计划先嵌入章纲，关系先作为有类型引用，避免无用途的独立表 |
| R11 / 中 | 技术设计启动段要求“所有功能必须插件化”，启动提示词又禁止普通函数 Agent；并没有对应业务必要性或协议 | [D03](decisions.md#d03显式持久化状态机先于编排框架)、[D06](decisions.md#d06题材插件先作为固定版本数据规则包) 采用职责与规则扩展边界，而非限定实现形式 |
| R12 / 中 | UI/UX 主要列页面和技术；没有未保存状态、候选比较、过期处理、任务恢复和可访问性 | [交互设计](ux.md) 按真实作者任务定义操作与异常恢复；复杂图谱后置 |
| R13 / 高 | 全套资料没有可执行的质量基线；Critic 的“爽点/弃读风险”也缺乏真实验证依据 | [验证策略](validation.md) 区分工程不变量、模型适配和作者评审；不把模型自评分当商业效果 |

## 4. 尚待实施或实验确认

- 具体依赖版本与运行命令已由 T00 写入根目录 README 和锁文件；实际兼容与运行证据见 [T00 验证记录](t00-validation.md)。真实供应商与模型留给 T04，不假定已有凭据。
- token/费用默认预算、章节长度和风格默认值：由实际写作成本与作者反馈调整。
- 检索质量是否需要向量增强、状态机是否需要 LangGraph：以 T10 的失败样本和维护成本评估。
- 文笔、人物弧光与伏笔质量是否达到作者预期：需要真实文本和人工评审，不能通过文档审阅证明。

本轮已经收敛实施所需的结构性选择，没有把上述实验问题伪装成设计已解决的问题。
